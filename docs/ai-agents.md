# AI agents and API discovery

WP-SKOS tells AI agents and other API clients how to use your vocabularies, with no setup. It generates two documents from the taxonomies enabled in **Settings → WP-SKOS**:

| URL | What it is |
|---|---|
| `/llms.txt` and `/wp-skos/llms.txt` | A short guide in the [llms.txt](https://llmstxt.org/) format: what the site offers, how to find a concept and the posts about it, and a list of the vocabularies and endpoints. |
| `/.well-known/api-catalog` | A machine-readable list of the site's APIs, as defined by [RFC 9727](https://www.rfc-editor.org/rfc/rfc9727). |

Both list only taxonomies you've enabled, plus URL patterns and links. They don't list individual terms or posts. Neither exists until at least one taxonomy is enabled, and both need pretty permalinks, like the rest of the plugin.

{: .note }
> llms.txt is a proposed convention, not a standard, and major AI crawlers don't generally read it yet. It's most useful when someone points an agent at your site. It doesn't affect search rankings or control what crawlers may do; that remains the job of `robots.txt`.

## Whole-vocabulary export

`/wp-skos/export/{taxonomy}.jsonld` returns one enabled vocabulary as a single JSON-LD file: its concept scheme and every concept the visitor is allowed to see. It's useful for building a local index. For individual lookups, search is much lighter.

Each export builds every concept's document and writes nothing to the database. A vocabulary of about 750 terms took about 12 seconds in testing. Only one export of a vocabulary runs at a time, and a second request meanwhile gets `503` with a `Retry-After` header. See [Exporting to a triple store](skosmos-rest-api.html#exporting-to-a-triple-store) for loading the file into other tools.

## If you already have an llms.txt

WP-SKOS only answers requests that WordPress would otherwise answer with a 404. A real `llms.txt` file, or one generated by another plugin, keeps working and takes priority at `/llms.txt`. The WP-SKOS guide stays available at `/wp-skos/llms.txt`, so you can link to it from your own file.

These locations are defined relative to the domain root. On a site installed in a subdirectory, such as `example.com/blog`, the documents are served under that subdirectory, where agents that only check the domain root won't find them.

## Filters

| Filter | Purpose |
|---|---|
| `wpskos_llms_txt` | Change the generated guide's text. |
| `wpskos_serve_root_llms_txt` | Return `false` to stop serving `/llms.txt`, leaving only `/wp-skos/llms.txt`. |
| `wpskos_allow_export` | Return `false` to turn off the whole-vocabulary export, for all taxonomies or for one. This may suit a very large taxonomy on modest hosting. |

```php
add_filter( 'wpskos_llms_txt', function ( $guide ) {
	return $guide . "\n## Licensing\n\n- [Reuse terms](https://example.com/license/): How this vocabulary may be reused.\n";
} );
```
